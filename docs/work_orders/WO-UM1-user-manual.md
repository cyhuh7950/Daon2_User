## 1. 목표

- 초보자는 매뉴얼 흐름을 따라 첫 업무를 끝까지 진행할 수 있다.
- 숙련자는 필요한 화면 설명을 목차·찾아보기로 바로 찾을 수 있다.
- 모든 화면 설명에 **기능·목적, 사용 순서, 화면의 주요 항목 설명**이 들어간다.

## 4. 매뉴얼 구성

### 4.1 1부 처음 시작하기 (업무 흐름)

따라 하면 첫 업무가 끝나는 순서로 쓴다. 각 단계는 "무엇을 하는지 → 따라 하기(번호 목록) → 끝났는지 확인하는 법 → 자세히: 2부 ○○" 순서를 지킨다.

1. 이 설명서 읽는 법 (초보자는 1부부터, 숙련자는 2부·찾아보기로)
2. 가입과 로그인
3. 노트북 만들기
4. 자료(Source) 올리기
5. 질문하고 근거 확인하기
6. 스튜디오로 자료 만들기와 대화로 고치기
7. 문서 작성으로 제안서 만들기
8. 내려받기와 로그아웃

## 5. 화면 설명 공통 틀

2부·3부의 모든 화면은 아래 순서와 제목을 그대로 쓴다.

| 순서 | 제목 | 작성 규칙 |
| --- | --- | --- |
| 1 | 기능·목적 | 이 화면에서 무엇을 하는지, 왜 쓰는지. 2~3문장 |
| 2 | 쓸 수 있는 사람 | 역할(관리자·편집자·열람자 등)과 권한 |
| 3 | 사용 순서 | 번호 목록. 버튼·메뉴 이름은 화면 문구와 똑같이 **굵게** |
| 4 | 화면 구성 | 번호를 단 그림 + 표(번호 / 항목 / 설명 / 비활성 조건) |
| 5 | 주의·오류 | 표(화면 메시지 / 원인 / 조치) |
| 6 | 관련 | 1부 해당 단계, 이어지는 화면 |

작성 원칙:

- 화면 문구는 실제 화면 문구 파일(`packages/ui/src/*messages*.js` 등)과 대조해 똑같이 쓴다.
- 내부 주소·키·토큰·호스트 목록은 쓰지 않는다. 현재 §16 허용 목적지 호스트 목록은 "관리자 화면에서 확인" 안내로 바꾼다(F-14).
- 문장은 짧게, 한 문장에 한 동작. 전문 용어는 처음 나올 때 풀이하고 부록 B에 모은다.

## 8. 완료 기준

1. 1부를 ysna에서 처음부터 끝까지 그대로 따라 해 첫 업무(노트북 → 자료 → 질문 → 스튜디오 산출물 → 문서 작성 → 내려받기)가 끝난다.
2. 4.2·4.3 표의 모든 화면에 5절 6개 제목과 번호 그림이 있다.
3. 원본 md·docx·pdf·웹 공개 사본·목록 파일이 한 명령으로 만들어지고, ysna가 보내는 매뉴얼 해시가 원본과 같다(배포 후).
4. 매뉴얼 시험 전부와 새 시험 4개가 통과하고, 전체 시험 실패가 기준선보다 늘지 않는다.
5. 검증 보고서 F-01·F-02·F-03·F-14가 해소된다.
6. 시험 노트북·예시 자료를 지운 것을 확인한다.
