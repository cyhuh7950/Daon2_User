# WO-F7. 오디오 개요 — 선택 가능한 TTS 엔진

| 항목 | 내용 |
| --- | --- |
| 대상 계획 항목 | F7-02(모델 선정), F7-03(오디오 생성기), F7-04(후처리 Job·Range 스트리밍), S2-13(오디오 플레이어) |
| 상태 | **승인(2026-10-26, 권고안) → 구현됨**(편차는 §8) |
| 선행 | Studio v2 큐·워커·Asset 저장(완료). 동영상(F7-05, S2-14)은 이 WO 범위 밖 |
| 기준 설계서 | §7.6, §9, §10, §6.6, ST-08 |
| 결정 근거 | `docs/04_test_reports/deploy/tts-environment-check.md`, 2026-10-26 청취 평가(사용자) |

## 1. 결정된 것

| 항목 | 결정 |
| --- | --- |
| 기본 TTS 엔진 | **supertonic**(사용자 결정, 청취 평가 후). 한국어, 남 5·여 5 보이스, CPU RTF 약 0.48(실측, ysna-server) |
| 선택 가능 | TTS 엔진은 **설정으로 고른다**. 후보 엔진은 같은 HTTP 규격(OpenAI 호환 `/v1/audio/speech`)을 쓰는 것만 등록할 수 있다. 후보: supertonic(기본), qwen3-tts(느림: RTF 약 6.4, 메모리 5~7.5 GiB, 한국어 모국어 음색은 `sohee` 하나) |
| 엔진 실행 위치 | 사용자의 음성 엔진 서버(`~/deploy/voice`, 엔진별 컨테이너). Daon2-User는 호출만 한다 |

## 2. 현재 상태

- `audio_overview` 유형은 정의돼 있으나(`studio_v2_types.py`, phase "3") `tts_enabled`가 꺼져 있어 타일이 비활성이다.
- Provider 설정에 `text_to_speech` 능력(capability) 이름이 있고 DB 제약(0040)에도 있다. 그러나 STT 선례(`from_native_asr_metadata`)는 모델 ID·해시를 코드에 고정한 방식이라 TTS에 그대로 쓸 수 없다.
- 오디오 생성기, 음성 합성 호출, 후처리, Range 스트리밍, 플레이어는 없다.

## 3. 결정이 필요한 사항

| ID | 질문 | 권고안 | 대안 |
| --- | --- | --- | --- |
| D1 | 엔진 선택 단위 | **조직(워크스페이스) 설정 1개 + 생성 때 보이스 2개 선택**. 엔진은 관리자가 정하고, 사용자는 화자 A·B 보이스만 고른다 | 생성할 때마다 엔진 선택(엔진별 속도 차이가 커서 비권고) |
| D2 | 엔진 등록 방식 | 기존 Provider 연결에 `text_to_speech` 능력으로 등록(주소, 비밀 참조, 엔진 종류). 모델 목록은 `/info`·`/v1/voices`로 읽는다 | 별도 TTS 설정 테이블 |
| D3 | 외부 전송 정책 | 음성 서버는 **다른 호스트**라 스크립트 텍스트가 서버 경계를 넘는다. 기존 `egress_policy` 판정을 거치게 하고, 사용자의 서버 주소만 허용한다(설계서 §10 "오디오·영상 합성 외부 서비스도 동일") | 정책 면제(비권고) |
| D4 | 라이선스 | supertonic 모델은 **BigScience Open RAIL-M**(상업 사용 가능, 용도 제한 있음)이다. 우리는 모델 파일을 배포하지 않고 호출만 한다. 제품 사용 전에 법무·책임자가 조건을 확인한다 | qwen3-tts(Apache-2.0 표기, 본문 미확인)를 기본으로 |
| D5 | 생성 시간 한도 | 5분 분량 기준 supertonic 약 2.4분, qwen3-tts 약 32분. 작업 제한 시간을 **엔진별 설정**으로 두고, 초과 시 실패 사유를 보인다 | 고정 한도 |
| D6 | 오디오 형식 | WAV 원본을 만들고 ffmpeg로 mp3 인코딩(내보내기 `mp3`·`wav`) | WAV만 |

## 4. 작업

1. **TTS Provider 등록(F7-02 마무리)**: `text_to_speech` 연결 등록·확인(`/health`, `/info`, `/v1/voices`), API 키는 비밀 참조로만 보관, 확인은 "연결됨"이지 "합성 성공"이 아님을 표시한다. 설정 화면에서 엔진과 기본 보이스 2개를 고른다.
2. **오디오 생성기(F7-03)**: 두 단계. ① LLM이 `{script[{speaker, text, refs}], duration_est}` JSON을 만든다(근거 `refs` 검증은 기존 보고서와 같은 방식). ② 화자별 보이스로 문장 단위 합성 요청.
3. **후처리 Job(F7-04)**: 문장 WAV 연결·무음 삽입·mp3 인코딩, Asset 저장, 문장별 시작·끝 시간을 `segments`로 저장(스크립트 동기 표시용). 실패한 문장만 재시도하고 전체 한도는 D5를 따른다.
4. **Range 스트리밍(F7-04)**: `GET …/assets/{asset_id}`에 `Range` 지원(BFF의 허용표·버퍼링 구조를 바꾸지 않는 범위에서 확인, 불가능하면 별도 결정).
5. **플레이어(S2-13)**: 재생·속도·구간 이동, 스크립트 줄 하이라이트, 키보드 조작·스크린리더 라벨, 스크립트 텍스트 제공(접근성).
6. **타일 활성화**: Provider에 TTS가 연결되고 확인되면 `tts_enabled`가 켜진다. 아니면 "아직 제공하지 않음"과 이유를 보인다.

## 5. 시험

- 단위: 스크립트 검증, 화자 교대, 문장 분할, 재시도, 엔진 응답 오류 처리.
- 통합: 가짜 TTS 서버로 전 과정, egress 정책 차단, 키 비노출.
- E2E: WSL 스택 → 실제 supertonic 서버로 5분 분량 생성(시간·길이 측정), mp3 다운로드.
- UI: 플레이어 키보드·스크립트 동기, 타일 비활성 사유.
- **청취 품질은 사람이 확인**한다(자동 시험으로 통과 처리하지 않는다).

## 6. 범위 밖

동영상(F7-05, S2-14), 음성 복제, 대화 중 개입(설계서 5.2에서 제외), 외부(클라우드) TTS.

## 7. 위험

- 음성 서버(ysna-server)가 꺼져 있거나 느리면 생성이 실패한다. 상태 확인과 명확한 오류 문구가 필요하다.
- qwen3-tts를 선택하면 서버 메모리를 거의 다 쓴다(다른 서비스와 공유). 선택지로 두되 기본값이 아니다.
- 한국어 숫자·약어 읽기(예: "1,000,000원")는 엔진마다 다르다. 스크립트 생성 단계에서 읽는 형태로 풀어 쓰도록 지시하고, 청취 평가에서 확인한다.

## 8. 구현 결과와 편차 (2026-10-26)

| 항목 | 초안 | 구현 |
| --- | --- | --- |
| D2 엔진 등록 | Provider 연결 화면에 `text_to_speech`로 등록 | **배포 설정 파일**(`DAON_TTS_CONFIG_FILE`, 키 포함 비밀 파일)로 등록한다. Provider 연결은 모델 해시를 코드에 고정하는 구조라 TTS에 맞지 않았다. 관리 화면 등록은 **WO-F7T로 구현**(화면에서 등록한 엔진이 배포 설정 파일보다 우선) |
| D1 선택 단위 | 조직 1개 + 생성 때 보이스 | 설정 파일의 기본 엔진 + 생성 설정의 `engine`·`voice_a`·`voice_b`(설정 파일에 등록된 것만 허용, 설정 대화상자에 선택지) |
| 자산 저장 | 객체 저장소 Asset | **DB `studio_v2_assets.content bytea`**(0077). 워커에 객체 저장소가 연결돼 있지 않고 삭제가 자동 연쇄(FK)되기 때문. 한도 32 MiB |
| D3 외부 전송 | 정책 게이트 | 엔진 `provider_kind` 기본 `external_api` → 기존 `StudioEgressGate`(허용 목적지·크기·마스킹). 정책이 마스킹을 요구하면 개인 식별 패턴을 가려 전송 |
| D6 형식 | mp3·wav | **mp3만**(lameenc 인코딩). wav 내보내기는 400 |
| Range | `…/assets/{asset_id}` | `GET …/outputs/{id}/audio`(API: 단일 Range 206/416). **BFF는 허용 헤더만 전달하고 Range를 넘기지 않아** 전체 파일(200)을 돌려준다. 플레이어는 파일 전체를 받아 재생·이동한다 |
| 스크립트 | text | `text`(자막용 원문) + `speech`(읽는 형태, 숫자 풀어쓰기) + 줄별 `start_ms`·`end_ms` |

검증: 단위 23건, API HTTP(Range) 1건, UI 1건, 실제 LLM + 실제 supertonic E2E(`e2e_studio_v2.py --audio`: 10줄, 약 88초 분량, 생성 77~84초, mp3 약 1.4 MB). **미검증**: 청취 품질(사람), 실제 앱 화면에서의 오디오 생성 조작(개발 테넌트에 LLM 모델이 없어 불가, 시험 페이지로 대체), 5분 이상 분량의 생성 시간, 라이선스 조건 확인.
