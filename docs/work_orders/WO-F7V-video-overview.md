# WO-F7V. 동영상 개요 — 슬라이드 + 내레이션 영상

| 항목 | 내용 |
| --- | --- |
| 대상 계획 항목 | F7-05(동영상 생성기·챕터), S2-14(동영상 플레이어·챕터) |
| 상태 | **승인(2026-10-26, 권고안·내부 배포) → 구현됨**(편차는 §6) |
| 선행 | WO-F7(TTS 엔진 선택·오디오 생성·DB 자산 `content`)은 완료. 슬라이드 생성기(`SlidesGenerator`)와 글꼴(NanumGothic)이 이미 있다 |
| 기준 설계서 | §7.6(`{scenes[{slide, narration, duration}]}` → 합성, 검증: 장면 수·길이 합), §6.6(플레이어 + 챕터 목록), ST-09(MP4) |

## 1. 재사용하는 것

| 재사용 | 위치 | 비고 |
| --- | --- | --- |
| 장면 JSON 검증 방식 | `studio_validation.validate_slides` | 슬라이드(제목·글머리·표·notes·refs) 구조를 그대로 쓴다 |
| TTS 엔진 선택·정책 게이트·마스킹 | `tts_engines.py`, `studio_audio.py` | 내레이션 합성에 같은 설정·같은 외부 전송 판정 |
| 자산 저장 | `studio_v2_assets.content`(0077), `kind='mp4'` 허용 | **새 마이그레이션 없음**. 한도 32 MiB |
| 글꼴 | `assets/NanumGothic-Regular.ttf`, Pillow | 슬라이드 이미지를 서버에서 그린다 |
| 타일·문구 | `video_overview`(phase "4", 형식 `mp4`) | `tts_enabled`와 같은 방식으로 활성화 조건만 추가 |

## 2. 결정이 필요한 사항

| ID | 질문 | 권고안 | 대안 |
| --- | --- | --- | --- |
| D1 | 영상 합성 도구 | **ffmpeg 실행 파일**을 API 이미지에 넣고 서브프로세스로 호출한다(H.264 + AAC, 정지 이미지 + 오디오). 파이썬만으로는 H.264 인코딩을 할 수 없다 | `imageio-ffmpeg` 휠(약 25~30 MB, x86_64·aarch64 모두 있음) — 이미지에 apt를 쓰지 않아도 된다 |
| D2 | **라이선스** | 일반 ffmpeg 빌드는 libx264(GPL)를 포함한다. 별도 프로세스로 실행하고 이미지를 **외부에 배포하지 않는 내부 배포**라면 의무가 작지만, 이미지를 배포·납품하면 GPL 고지·소스 제공 의무가 생긴다. **배포 형태를 확인해 주세요** | WebM(VP9+Opus, BSD 계열 libvpx/libopus)로 mp4 대신 webm을 내보낸다(브라우저 재생 가능, PowerPoint 등에서는 불가). 또는 LGPL 빌드 + 하드웨어/OpenH264 |
| D3 | 장면 구성 | 슬라이드 1장 = 장면 1개. 슬라이드 생성기와 같은 구조에 **장면별 내레이션**(`narration`, 근거 `refs`)을 더해 LLM이 한 번에 만든다. 기존 슬라이드 산출물을 입력으로 받는 방식은 후속 | 기존 슬라이드 산출물을 골라 영상화 |
| D4 | 화자 | 내레이터 **1명**(보이스 A만 사용). 2화자 대화형 영상은 후속 | 오디오 개요처럼 2화자 |
| D5 | 해상도·형식 | 1280×720, 5 fps 정지 화면, H.264 baseline + AAC 64 kbps → 5분 영상 약 3~6 MB(자산 한도 32 MiB 이내). 모든 슬라이드는 같은 기본 테마(라이트) | 1920×1080(용량 2배) |
| D6 | 자막 | **WebVTT 자막 트랙 자동 생성**(내레이션 줄 단위). 접근성 요구(설계서 접근성 행)와 청각 접근성을 위해 기본 포함 | 자막 없음 |
| D7 | 챕터 | 장면 = 챕터. 본문 JSON에 `chapters[{title,start_ms,end_ms}]`, MP4에도 챕터 메타데이터를 기록한다. 플레이어는 목록 클릭으로 이동 | 본문 JSON만 |
| D8 | 시간 한도 | TTS 합성(문장 단위, 오디오 개요와 같은 한도 `max_total_seconds`) + 슬라이드 그리기(장면당 1초 미만) + ffmpeg(5분 영상 약 10~30초, 장면당 1회 인코딩 후 연결). 워커 메모리 768 MiB 안에서 ffmpeg `-threads 2` | 별도 영상 워커 컨테이너 |

## 3. 작업

1. **장면 검증기**: `validate_video_scenes` — 장면 3~20개, 장면당 narration 600자 이하, 근거 라벨 환원·숫자 앵커 검사(오디오와 같은 규칙), 슬라이드 제목·글머리 한도는 `validate_slides`와 같다.
2. **슬라이드 렌더러**: Pillow로 1280×720 PNG(제목 장면·글머리·표·두 열). 텍스트 넘침은 말줄임 + 경고(인포그래픽 `layout`/`wrap` 재사용).
3. **합성 파이프라인**: 장면별 내레이션 TTS(오디오 개요의 `synthesize_dialogue`를 1화자로 호출) → 장면별 길이 확정 → 장면 이미지 + 오디오를 ffmpeg로 mp4 한 파일로 합성 → 자막(VTT)·챕터 계산.
4. **자산·내보내기**: `kind='mp4'`(영상), 자막은 본문 JSON의 `scenes[].narration`에서 요청 시 VTT로 변환(`GET …/exports/vtt`). 내보내기 형식: `mp4`, `vtt`.
5. **API**: `GET …/outputs/{id}/video`(오디오 라우트와 같은 Range 처리), 자막은 `exports/vtt`. BFF 허용 경로 추가.
6. **플레이어(S2-14)**: `<video controls>` + 자막 `<track>`(blob) + 챕터 목록(현재 챕터 강조·클릭 이동) + 속도 선택, 키보드 조작·스크린리더 라벨.
7. **이미지**: API 이미지에 ffmpeg 추가(D1·D2 결정에 따름), `uv.lock`·보안 점검(pip-audit/이미지 스캔) 갱신.
8. **시험**: 단위(검증기, 렌더러 레이아웃, 장면 타이밍·챕터·VTT, ffmpeg 호출 인자), HTTP(Range), UI(플레이어·챕터), E2E(실제 LLM + 실제 TTS + 실제 ffmpeg: 5장면 영상 생성·재생 응답·ffprobe로 길이·챕터·코덱 확인).

## 4. 범위 밖

슬라이드 애니메이션, 영상 편집, 배경 음악, 2화자 영상, 사용자 이미지 삽입, 외부 영상 생성 서비스, Desktop·Mobile 재생(Phase 5).

## 5. 위험

- **라이선스(D2)**: ffmpeg 빌드의 GPL 여부. 결정 전에는 이미지를 만들지 않는다.
- 이미지 크기 증가(ffmpeg 약 25~100 MB).
- 영상 길이가 길수록 TTS 시간이 지배적이다(오디오 개요와 같다: 5분 기준 supertonic 약 2.4분).
- 정지 화면 영상은 글자 크기가 작으면 읽기 어렵다. 슬라이드 글자 크기 하한(제목 44px, 본문 28px 이상)을 두고 넘치면 경고한다.
- 청취·시청 품질은 자동 시험으로 통과 처리하지 않는다(사람 확인).

## 6. 구현 결과와 편차 (2026-10-26)

| 항목 | 초안 | 구현 |
| --- | --- | --- |
| D1 합성 도구 | ffmpeg 실행 파일 | **`imageio-ffmpeg==0.6.0` 휠**(번들 정적 ffmpeg 7.0.2, x86_64·aarch64). `DAON_FFMPEG`로 경로를 바꿀 수 있고, 실행 파일이 없으면 동영상 타일은 비활성이다 |
| D2 라이선스 | 내부 배포 확인 | 사용자 확인(2026-10-26): **이미지를 외부에 배포하지 않는 내부 배포**. 외부 배포로 바뀌면 번들 ffmpeg(libx264 포함 GPL 빌드)의 고지·소스 제공 의무를 다시 검토해야 한다 |
| D3~D5 | 장면 3~20·내레이터 1명·1280x720 | 그대로. 5 fps 정지 화면, H.264(crf 30, veryfast, stillimage) + AAC 64 kbps. 5장면 약 87초 영상이 약 0.7 MB |
| D6 자막 | WebVTT | `GET …/exports/vtt`(본문 `scenes[].cues`에서 생성). 플레이어는 `<track kind="captions">`로 기본 표시 |
| D7 챕터 | 장면=챕터 | 본문 `chapters[]` + mp4 챕터 메타데이터(ffmetadata). 플레이어는 목록 클릭으로 이동·현재 챕터 강조 |
| D8 한도 | 오디오와 같은 `max_total_seconds` | 같음. ffmpeg는 300초 제한·`-threads 2` |
| Range | 오디오와 같이 | API는 단일 Range(206/416), BFF는 전체 파일 전달. 미디어 라우트는 `_serve_media`로 공통화(`X-Media-Duration-Ms`) |
| 마이그레이션 | 없음 | 없음(0077의 `content` 열과 `kind='mp4'` 재사용) |

검증: 단위 12(검증기·그리기·타임라인·VTT·챕터·**실제 ffmpeg 합성(H.264+AAC+챕터 3개 확인)**·생성기·정책 마스킹·오류), 타입 1, HTTP 1, UI 1, BFF 2, 실제 LLM+supertonic+ffmpeg E2E(`--video`: 5장면, 생성 80초, mp4 700 KB, VTT 1.9 KB). **미검증**: 영상·음성의 시청 품질(사람), 실제 앱 화면에서의 조작(개발 테넌트에 LLM이 없어 불가), 5분 이상 분량의 생성 시간, 슬라이드 글자 크기가 큰 화면에서 충분한지(현재 본문 32px, 내용이 화면 위쪽에 모여 개선 여지가 있다).
