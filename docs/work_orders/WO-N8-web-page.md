# WO-N8 웹 페이지 만들기(인터랙티브 페이지) 설계

- 상태: 승인됨(신산님 2026-11-25) · 작성 2026-11-25
- 출처: WO-N1 설계서 §4 N1-8(후보, 설계만), 최종 보고 §7 B 묶음
- 대화 결정(신산님 2026-11-25): 자유 HTML 방식, 요청은 사용자가 적는 글, 주 용도는 앱 안에서 보기, 내려받아 다른 곳(제안서 첨부·고객 전달·서버 게시)에도 쓸 수 있으면 좋음, 만드는 방법은 B안(내용 먼저·모양 나중)
- 검토 뒤 결정(신산님 2026-11-25): 근거 부족 문장은 페이지에 넣지 않음, 페이지 안 계산 기능(새 숫자를 만드는 스크립트)은 허용하지 않음

## 1. 목적과 이유

사용자가 노트북에서 **요청 글**을 적으면, 노트북 소스 내용을 바탕으로 그 요청에 맞는 **웹 페이지(HTML) 한 장**을 만든다.

- 요청 예: "이 약관의 보장 내용을 고객이 보기 쉬운 안내 페이지로", "제안서 핵심을 한 장짜리 소개 페이지로".
- 결과는 앱 안에서 보는 것이 주 용도다.
- 그 자체로 열리는 HTML 파일로 내려받아 제안서 첨부·고객 전달·서버 게시에도 쓸 수 있게 한다.

기존 스튜디오 산출물(보고서·슬라이드 등)은 정해진 화면 부품으로만 그린다. 그래서 "요청에 맞는 자유로운 모양"을 만들 수 없었다. 이 기능은 모양을 모델에 맡기되, 내용은 지금처럼 소스 근거로 확인한다.

## 2. 목표 / 비목표 / 실패로 보는 것

**목표**
- 스튜디오 새 유형 **웹 페이지**(`web_page`). 타일을 누르고 요청 글(필수)과 소스 선택으로 만든다.
- 내용의 숫자·고유값은 소스 근거로 확인한다. 근거 없는 문장은 빼거나 "근거 부족"으로 표시한다.
- 앱 안에서는 격리된 칸에 띄우고, 페이지 안 스크립트는 보여 주기 동작(탭·펼치기·정렬)만 한다. 새 숫자를 계산해 보여 주는 기능은 넣지 않는다(신산님 결정).
- 페이지 옆(또는 아래)에 근거 목록을 둔다. 근거를 누르면 소스 원문으로 이동한다.
- 그 자체로 열리는 HTML 한 장으로 내려받는다. 출처 목록을 파일에 넣을지 고를 수 있다.
- 고치기 두 가지:
  - 요청 글을 바꿔 다시 만들기
  - 대화로 고치기(내용 단계를 고친 뒤 모양을 다시 입힘)

**비목표(이번에 하지 않음)**
- 공개 주소로 올려 공유하기(예전 결정: 공개 URL 없음)
- 외부 글꼴·외부 라이브러리·외부 이미지·외부 데이터 불러오기
- 페이지 안 입력 내용을 서버에 저장하는 폼
- 페이지 안 계산기(입력값으로 새 숫자를 계산해 보여 주기)
- 페이지 HTML을 사용자가 손으로 직접 고치기(고치기는 요청 바꿔 다시 만들기와 대화로 고치기만)
- 여러 페이지로 된 사이트
- 웹 검색으로 내용 채우기(D-02 웹 제외 유지)

**실패로 보는 것(동작해도)**
- 내려받은 파일이나 앱 화면에 소스에 없는 숫자·사실이 들어감
- 페이지 스크립트가 앱(쿠키·저장소·부모 화면)에 접근하거나 바깥으로 네트워크 요청을 보냄
- 내려받은 파일이 앱이 없으면 깨짐(외부 자원에 기댐)
- 페이지 칸 때문에 앱 화면 전체가 스크롤됨(창 배치 원칙 위반)

## 3. 제약

- **근거 원칙(WO-C1)**: 지식 산출물은 소스 근거로만 쓴다. 숫자·날짜·식별자 대조는 기존 `_evidence_anchors`를 쓴다.
- **외부 전송**: 모든 모델 호출은 기존 `StudioEgressGate`를 거친다. 새 우회 경로를 만들지 않는다.
- **격리**
  - 앱 안 표시: `iframe srcdoc` + `sandbox="allow-scripts"`. `allow-same-origin`·`allow-forms`·`allow-popups`·`allow-top-navigation`은 넣지 않는다.
  - 페이지 문서 안에 CSP를 넣는다: `default-src 'none'; img-src data:; style-src 'unsafe-inline'; script-src 'unsafe-inline'; font-src data:; connect-src 'none'; form-action 'none'; base-uri 'none'`.
  - 서버는 저장 전에 외부 주소(`http(s)://`, `//`, `url(` 외부)를 지우거나 거부한다.
  - `<script src>`, `<link href>`, `<iframe>`, `<object>`, `<embed>`, `<base>`, `<form action>`, `<meta http-equiv="refresh">`는 거부·제거한다.
  - 내려받은 파일에도 같은 CSP 메타를 넣는다.
- **저장 한도**: 판 하나 2 MiB(`MAX_REVISION_BYTES`). HTML 상한을 따로 두어(예: 400 KB) 넘으면 실패 처리한다.
- **내려받기 정책**: 기존 조직 내려받기 정책(추가 인증 등)을 다른 산출물과 똑같이 따른다.
- **화면**
  - 창 배치 원칙: 페이지 칸과 근거 칸은 각 칸 안에서 스크롤하고, 앱 페이지 전체 스크롤은 없다.
  - 문구는 `studio-messages.ko.js`에 모은다. 영문 머리말을 쓰지 않는다(DESIGN.md).
- **배포**: ysna(ARM64). 새 외부 서비스·새 키·새 비용 없음. 기존 모델 연결(Media Bridge 등)만 쓴다.

## 4. 만드는 방법(검토한 세 가지와 선택)

| 방법 | 내용 | 장단점 |
| --- | --- | --- |
| A. 한 번에 HTML | 모델이 요청·근거를 받아 완성 HTML을 바로 씀. 서버는 정리·숫자 대조만 | 단순·빠름. 내용과 모양이 섞여 근거 검사가 거칠고, 긴 페이지는 출력 한도에서 잘림 |
| **B. 내용 먼저, 모양 나중(선택)** | 1단계 근거 붙은 내용(JSON) → 서버 근거 검사 → 2단계 검사 통과 내용만으로 자유 HTML | 모양 자유 + 내용 근거 확인. 호출 2회라 더 걸림 |
| C. 정해진 부품 조합 | 앱 부품을 골라 배치 | 가장 안전하지만 자유 모양이 아니라 제외 |

신산님이 B를 골랐다. 이유: 요청에 맞는 자유로운 모양을 살리면서, 밖으로 나가는 파일에 근거 없는 내용이 섞일 위험이 가장 작다.

## 5. 정한 동작(신산님 결정과 그에 따른 것)

### 5.1 만들기 흐름
1. 스튜디오 **웹 페이지** 타일 → 설정 창에서 **요청 글**(필수, 최대 2,000자)을 적고 소스를 고른 뒤 **만들기**.
2. 카드 진행 문구: "내용 만드는 중" → "페이지 만드는 중" → 완료. 다른 유형과 같이 취소할 수 있다.
3. **1단계(내용)**
   - 모델이 요청과 근거 묶음(기존 `ContextPack`)으로 페이지 내용을 만든다.
   - 내용: 제목, 절 목록, 절마다 문장·목록·표·숫자 항목. 문장·항목마다 근거 번호 `refs`가 붙는다.
   - 서버는 보고서와 같은 규칙으로 검사한다: 근거 번호 유효성, 숫자·고유값이 인용 근거에 있는지.
   - 근거 없는 문장은 "근거 부족"으로 표시해 1단계 내용에 남기되, **2단계(HTML)에는 넣지 않는다**(신산님 결정). 앱의 근거 칸에 "근거 부족으로 뺀 내용"으로만 보인다.
   - 근거 있는 내용이 하나도 없으면 실패(`STUDIO_VALIDATION_FAILED`).
4. **2단계(모양)**
   - 모델에 1단계 내용 중 **근거 확인된 부분**과 요청 글만 준다. 근거 부족 문장과 소스 원문은 주지 않는다.
   - 모델은 "이 내용만 쓰고, 새 숫자·사실을 더하지 말 것, 계산식·숫자 상수를 스크립트에 넣지 말 것, 외부 자원 금지, 한 파일"이라는 지시로 HTML 한 장을 만든다.
   - 서버 검사:
     - 위험 요소 제거·거부(§3)
     - CSP 메타 삽입
     - HTML의 보이는 글과 **스크립트 안 글**에서 뽑은 숫자·고유값이 1단계의 근거 확인된 글 집합 안에 있는지 검사한다. 벗어나면 한 번 다시 시도하고, 그래도 벗어나면 실패한다.
     - 대조 예외(제 판단): 요청 글에 사용자가 직접 쓴 숫자, 1~20의 단독 순번(단계·탭 번호), 근거 번호(S1…)
     - 1단계 절 제목이 HTML에 모두 들어갔는지 검사한다(제 판단). 빠지면 한 번 다시 시도하고, 그래도 빠지면 실패한다.
     - 크기 상한
   - 근거 번호 표시: HTML 안에서 근거가 붙는 자리는 `data-ref="S1"` 속성으로 표시하게 지시한다. 앱이 이를 눌렀을 때 근거로 이동시키는 데 쓴다.
5. 저장: 판 내용 = `{body: {title, request, sections(1단계), html(2단계)}, evidence}`. 1단계 내용과 HTML을 함께 보관한다.

### 5.2 보기
- 카드를 열면 두 칸으로 나뉜다.
  - 왼쪽(넓은 칸): 격리 iframe에 HTML
  - 오른쪽(좁은 칸): 근거 목록(S1…, 자료 이름·출처·발췌, 기존 근거 창 재사용)
- 좁은 화면에서는 위아래로 쌓고, 각 칸 안에서 스크롤한다.
- 페이지 안 `data-ref` 요소를 누르면 근거로 이동한다.
  - iframe은 `allow-same-origin`이 없으므로 `postMessage`로 알린다.
  - 앱은 출처가 그 iframe인지, 메시지 모양이 `{type:"daon-ref", ref:"S\d+"}`인지 확인한 뒤에만 반응한다.
  - 이 연결 스크립트는 서버가 HTML 끝에 넣는 고정 코드다(모델이 쓰지 않음).
- 근거 부족으로 뺀 내용이 있으면 근거 칸 위에 "근거 부족으로 뺀 내용 N건" 한 줄과 그 목록을 보인다. 페이지(HTML) 자체에는 없다.

### 5.3 고치기
- **요청 바꿔 다시 만들기**: 기존 "설정 바꿔 다시 만들기"와 같이, 요청 글을 고쳐 새 판을 만든다.
- **대화로 고치기**: 기존 대화로 고치기(WO-K5) 대상 유형에 `web_page`를 더한다.
  - 고치기는 1단계 내용(절·문장)에 적용한다. 고친 문장도 근거 규칙으로 검사한다.
  - 2단계 HTML은 **고친 안을 만들 때 함께 만든다**(제 판단). 지금 "적용"(`apply_edit_turn`)은 모델을 부르지 않는 DB 처리라서, 고친 안 작업(`studio_chat_edit_runner`)에서 1단계 수정과 HTML 재생성을 함께 하고, 적용 전에 바뀐 페이지를 미리 보게 한다. 대가: 버린 안에도 모델 호출 비용이 든다.
  - HTML 재생성이 실패하면 그 고친 안은 실패 상태가 된다. 1단계만 고쳐진 채 적용되는 일은 없다.

### 5.4 내려받기
- 형식은 `html` 하나다. 내려받을 때 "출처 목록 넣기"를 고를 수 있다(기본: 넣기).
- 넣으면 페이지 맨 아래에 "출처" 목록(근거 번호, 자료 이름, 쪽/구간)을 글로 붙인다.
- 연결용 고정 스크립트(`postMessage`)는 내려받은 파일에서 뺀다.
- 파일은 CSP 메타를 그대로 갖고, 외부 자원 없이 단독으로 열린다.

## 6. 만드는 사람에게 맡기는 것

- 1단계 JSON 스키마의 세부(블록 종류: 문단·목록·표·숫자 카드 정도)와 모델 지시문
- 2단계 출력 토큰 한도와 HTML 크기 상한의 정확한 값(모델 연결 한도 안에서)
- HTML 정리 방식(허용 목록 기반 정리 라이브러리를 쓸지, 자체 검사로 할지)
  - 서버는 Python이다.
  - 새 의존성을 더하면 ARM64 이미지에서 동작해야 한다.
- 숫자·고유값 대조에서 "보이는 글"을 뽑는 방법(태그·스크립트·스타일 제외)
- 근거 칸 너비 비율, 좁은 화면 전환 기준
- 진행 문구 단계 구분 값(기존 `progress.note` 방식)
- 설명서 절 추가(새 절 2-21 웹 페이지)

## 7. 시험과 완료 기준(요약)

- 서버 시험
  - 1단계 근거 검사: 근거 없는 숫자는 "근거 부족" 표시, 근거 0이면 실패
  - 2단계: 1단계에 없는 숫자가 HTML에 나오면 재시도 후 실패
  - 위험 요소(외부 `script src`, `iframe`, 외부 `url(`, `form action`, `meta refresh`, `base`)를 제거·거부
  - 근거 부족 문장이 2단계 입력과 HTML에 들어가지 않음
  - 스크립트 안 숫자 상수도 대조됨, 대조 예외(요청 숫자·순번·근거 번호) 동작, 절 제목 누락 시 재시도
  - 대화로 고치기: 고친 안에 새 HTML이 함께 저장되고, HTML 실패 시 고친 안이 실패 상태
  - CSP 메타가 들어감
  - 크기 상한을 넘으면 실패
  - 외부 전송 판정 호출 수가 모델 호출 수와 같음
  - 내려받기: 출처 넣기/빼기, 연결 스크립트 제거, 단독으로 열리는 구조
- 화면 시험
  - iframe `sandbox` 값(allow-scripts만)
  - `postMessage` 출처·모양 검사(다른 출처·모양은 무시)
  - 근거 칸 이동
  - 두 칸 각각 칸 안 스크롤
  - 근거 부족 경고
  - 대화로 고치기 대상 포함
- 실서버 확인(ysna)
  - 합성 약관 소스로 "고객 안내 페이지" 요청 → 페이지 표시
  - 근거 클릭 이동
  - 내려받은 HTML을 앱 밖에서 열어 외부 요청 0건(브라우저 네트워크 기록)
  - 대화로 고치기 한 번
  - 페이지 스크롤 없음

  - 제목·절 제목도 근거 대조: 근거 없는 숫자가 든 절 제목이면 그 절 전체가 근거 부족, 제목이면 페이지·카드 제목·파일 이름에 쓰지 않는다.
  - 대화로 고치기: 고친 블록은 그 블록 근거 번호의 자료 본문으로만 다시 판정한다. 표·수치 카드가 든 절은 통째 바꾸기·지우기를 막고, 표·수치 블록은 대화로 고치지 않는다.
  - 내려받기 선택 `include_sources`는 html 형식에서 0/1만 받는다. 예전 제품 스튜디오 화면에는 웹 페이지를 넣지 않았다.
