## 1. 확인한 Gemini Notebook 의 모습

### 1.1 화면에서 직접 확인한 것 (2026-11-23, 개인 계정)

| 영역 | 확인한 내용 |
| --- | --- |
| 노트북 홈 | 탭 **전체 / 둘러보기 / 컬렉션**, **추천 노트북**(출판사·언론사가 만든 공개 노트북, "전체 도서" 표시), **최근 노트북**, 노트북 검색, 격자/목록 보기 |
| 빈 노트북 | "노트북을 시작해 보세요" 안내와 시작 제안 3개(**새로운 주제에 관해 알아보기**, **새로운 항목 만들기**, **프로젝트 진행하기**) |
| 출처(소스) 칸 | **소스 추가**, **메모 만들기**. 안내 문구 "이제 메모를 소스와 함께 사용할 수 있습니다. 메모와 소스를 기반으로 채팅하고, 인용하고, 콘텐츠를 생성할 수 있습니다." |
| 소스 찾기 | 출처 칸 안의 검색창 "웹에서 새 소스를 검색하세요" + 범위 선택(**웹**/**Drive**) + 방식 선택(**Fast Research** 빠른 결과 / **Deep Research** 심층 보고서) |
| 소스 묶음 | 공개 노트북에서 소스가 **주제별 묶음**(예: Account and Management, Content Generation …)으로 접혀 있고, 묶음마다 체크 상자로 한꺼번에 질문 범위에 넣고 뺌 |
| 노트북 개요 | 노트북 위쪽에 제목·소스 수·날짜와 **요약 문단**, 그 아래 **추천 질문 3개** |
| 채팅 입력 | "질문하거나 창작하세요", 소스 수 표시, **연결된 앱 메뉴**: **웹**·**Google Drive** 켜고 끄기, **앱 연결**. 즉 소스 밖의 도구를 질문마다 켜고 끈다 |
| 스튜디오 | AI 오디오 오버뷰, 슬라이드 자료, 동영상 개요, 마인드맵, 보고서(New!), 플래시카드, 퀴즈, 인포그래픽. 산출물 목록에 길이·형식(예: 요약, 설명 동영상)·사용 소스 수·생성 시점 표시. 같은 주제를 여러 언어로 만든 동영상 개요가 나란히 있음 |
| 공유 | 노트북 **공유**, 공개 노트북은 **복사**로 내 노트북을 만듦 |

이 계정에서는 데이터 표·코드 실행·"사이트 만들기" 메뉴가 보이지 않았다. 요금제(Pro/Ultra/Workspace) 기능은 화면으로 확인하지 못했고 §1.2 문서 근거만 있다. 질문·생성은 사용자 계정에 기록이 남으므로 하지 않았다(답변 과정 표시의 실제 모양은 미확인).

## 3. 범위

- **들임(이번 WO)**: N1-1 ~ N1-7. 기존 구조 안에서 끝나거나 기존 연결(승인 지식·지식 연결·외부 전송 정책)을 재사용한다.
- **후보(설계만)**: N1-8 인터랙티브 페이지, N1-9 코드 실행 환경. 보안 격리 설계와 신산님 결정 후 별도 WO.
- **들이지 않음**: 공개 노트북·추천·컬렉션, 실시간 음성, 교과서·전자책 자료실, 개인 요금제·사용량 방식.

## 4. 기능별 설계

각 항목은 목적 → 사용자 흐름 → 화면 → 서버·데이터 → 정책·보안 → 시험·완료 기준 순서로 적는다.

### N1-1 답변 과정 보이기 (P1)

- **목적**: 답이 어떤 자료·어떤 판정을 거쳐 나왔는지 사용자가 직접 확인한다. 업무 검토자가 "이 답을 믿어도 되나"를 Citation 만으로 판단하기 어렵다.
- **흐름**: 답변 아래 접힌 **답변 과정** 을 펼치면 단계가 순서대로 보인다.
  1. 질문 범위: 체크한 소스 n개, 승인 지식 n개(이름), 켠 도구(N1-2)
  2. 근거 찾기: 검색한 구간 수, 고른 근거 구간 n개(소스·쪽)
  3. 외부 전송 판정: 허용/차단, 마스킹·삭제 적용 여부, 전송 크기(정책 이름만)
  4. 모델: 연결·모델·추론 수준(사용자가 고른 값 그대로)
  5. 검증: 인용이 근거 구간과 맞는지, 근거 부족 여부
- **보이지 않는 것**: 모델 내부 추론 문장, 프롬프트 원문, 비밀값, 내부 주소. **시스템이 한 일만** 보인다. 모델의 생각을 흉내 낸 문장은 만들지 않는다.
- **서버·데이터**: 질문 처리(`question_answering_service.py`)가 이미 만드는 값(검색 결과, 선택 근거, 외부 전송 판정 `question_egress.py`, 선택 모델)을 `run_results` 의 정규화 JSON 에 `process` 블록으로 남긴다. 새 테이블 없음. 응답과 `chat-history` 에 같은 블록을 싣는다. 과거 답변은 `process` 가 없으면 "과정 기록 없음"으로 표시.
- **정책·보안**: `process` 는 허용 목록 필드만 직렬화(이름·개수·코드). 외부 전송 판정은 결과 코드와 정책 버전만.
- **시험·완료**: 단위(필드 허용 목록, 비밀 필드가 없을 것), 화면(펼침·접힘, 단계 순서), 실서버에서 근거 있음/근거 부족/외부 전송 차단 세 경우의 표시 확인.

### N1-2 질문 도구 켜고 끄기 (P1)

- **목적**: Gemini 의 "연결된 앱 메뉴"처럼 질문마다 소스 밖 도구를 켜고 끈다. Daon 에서 도구는 **승인 지식**, **지식 연결**(Daon2-RAG 문서 MCP·Daon2 지식 MCP·법령), **웹**(정책 허용 시)이다.
- **흐름**: 입력창 왼쪽 **도구** 버튼 → 켜고 끄는 목록. 기본값은 승인 지식 켬, 지식 연결은 연결된 것만 켬, 웹은 꺼짐. 노트북별로 기억한다(모델 선택과 같은 방식).
- **화면**: 입력창 아래 모델 선택 바 옆. 켠 도구 수를 배지로 표시.
- **서버·데이터**: 노트북·사용자별 선택 저장(`notebook_model_selections` 와 같은 구조 — 마이그레이션 1개). 질문 시 켠 지식 연결의 허용 도구만 호출(`knowledge_connector_service.py` 의 `KINDS`·허용 도구 목록 재사용). 도구에서 받은 근거는 Citation origin 을 구분해 표시(`daon_knowledge`, `connector:<kind>`, `web`).
- **정책·보안**: 웹 도구는 조직 외부 전송 정책에 허용 목적지가 있을 때만 선택 가능. 꺼진 도구는 서버가 호출하지 않는다(화면 값만 믿지 않음).
- **시험·완료**: 도구별 켬/끔에 따른 호출 여부 단위 시험, 정책 차단 시 웹 선택 불가, Citation origin 표시.

### N1-3 메모를 소스로 쓰기 (P1, 작음)

- **목적**: 정리한 메모를 질문·스튜디오 근거로 쓴다(Gemini 의 최신 기능과 같음).
- **흐름**: 메모에서 **소스로 사용** 을 켜면 출처 칸에 "메모" 표시가 붙은 소스로 나타나 체크 대상이 된다. 메모를 고치면 "새 버전으로 반영" 안내 후 반영.
- **서버·데이터**: 메모 내용을 텍스트 소스 버전으로 스냅숏(기존 "복사한 텍스트" 소스 경로 재사용). 메모 수정은 새 소스 버전 생성 → 기존 산출물의 "소스가 변경됨" 배지(이미 있음)가 그대로 동작.
- **정책·보안**: 메모는 이미 노트북 접근자에게 보이므로 공개 범위 변화 없음. 소스가 되면 외부 전송 대상이 될 수 있으므로 기존 소스와 같은 판정을 받는다.
- **시험·완료**: 메모 → 소스 생성·버전 증가, Citation 이 메모로 연결, 메모 삭제 시 소스 처리("원본 메모 없음" 표시).

### N1-4 노트북 개요와 추천 질문 (P1)

- **목적**: 처음 연 사람이 노트북 내용을 바로 파악하고 첫 질문을 쉽게 한다.
- **흐름**: 준비된 소스가 생기면 대화창 위쪽에 **요약 한 문단**과 **추천 질문 3개**. 누르면 입력창에 채워짐(자동 전송 안 함). 소스가 바뀌면 "개요 다시 만들기".
- **서버·데이터**: 소스 근거로만 만든다(근거 없는 일반 지식 금지 — WO-C1 원칙). 노트북별 1건 저장, 소스 버전 해시가 바뀌면 낡음 표시. 비동기(스튜디오 작업 큐 재사용).
- **정책·보안**: 생성은 모델 호출이므로 외부 전송 판정 대상. 차단되면 개요 없이 시작 제안만 보인다.
- **시험·완료**: 근거 없는 문장 없음(인용 확인), 소스 변경 시 낡음 표시, 차단 시 화면.

### N1-5 소스 묶음 (P2)

- **목적**: 소스가 많을 때 주제별로 묶고 한꺼번에 체크한다.
- **흐름**: 출처 칸에서 **묶음 만들기**, 소스를 끌어 넣거나 메뉴로 이동. 묶음 체크 상자는 안의 소스 전체를 체크한다(일부만 체크되면 중간 상태).
- **서버·데이터**: 노트북별 묶음 테이블(이름·순서)과 소스-묶음 연결(마이그레이션 1개). 질문 범위 계산은 기존처럼 소스 단위(묶음은 화면 편의).
- **시험·완료**: 묶음 체크 → 질문 범위 소스 목록이 정확히 같음, 9개 이상 체크 시 안내(기존 규칙) 유지.

### N1-6 생성 전 구성 확인 확대 (P2, 작음)

- **목적**: 오래 걸리고 비싼 슬라이드·동영상 개요를 만들기 전에 방향을 맞춘다.
- **현재**: 보고서만 `confirm_outline` 지원(`studio_generators.py`).
- **설계**: 슬라이드(장 목록·장별 요지), 동영상 개요(장면 목록·내레이션 요지)에 같은 멈춤-확정 흐름을 적용한다. 확정 전에는 TTS·영상 렌더링을 하지 않는다.
- **시험·완료**: 확인 켬 → 개요에서 멈춤, 확정 → 같은 개요로 생성, 취소 → 음성·영상 생성 비용 없음.

### N1-7 자료 찾기: 빠른 찾기 / 심층 조사 (P2, 차별점)

- **목적**: Gemini 의 Fast/Deep Research 를 업무형으로 들인다. **승인 지식과 내부 지식 연결을 먼저** 찾고, 웹은 정책 허용 시에만 찾는다.
- **흐름**: 출처 칸 검색창 "필요한 자료를 찾아보세요" + 범위(승인 지식 / 지식 연결 / 웹) + 방식(**빠른 찾기** / **심층 조사**).
  - 빠른 찾기: 후보 목록(제목·출처·관련 이유·미리보기) → 고른 것만 소스로 추가.
  - 심층 조사: 조사 계획 → 여러 단계 찾기 → 인용 달린 조사 보고서를 스튜디오 보고서로 저장 + 사용한 자료를 소스 후보로 제시.
- **서버·데이터**: 승인 지식은 `knowledge-packages` 검색, 지식 연결은 허용 도구(`search_document_evidence` 등), 웹은 기존 웹사이트 수집(`website_source_import.py`, 수집 권한 확인 유지). 심층 조사는 스튜디오 작업 큐에서 비동기로 실행하고 진행 단계를 표시한다.
- **정책·보안**: 웹 범위는 외부 전송 정책의 허용 목적지 안에서만. 소스 추가 전에 사람이 고른다(자동 추가 없음). 조사 보고서는 근거 없는 문장을 표시하거나 제외한다.
- **시험·완료**: 범위별 호출 제한, 정책 차단 시 웹 범위 비활성, 후보 → 소스 추가 → 질문 근거 사용, 심층 조사 보고서의 인용 검증.

### N1-8 인터랙티브 페이지 (후보, 설계만)

- **목적**: 소스로 대시보드·진행 관리·학습 도구 같은 한 장짜리 화면을 만든다(Gemini "make me a site").
- **설계 방향**: 스튜디오 새 유형. 결과는 **외부 스크립트·네트워크 없는** 단일 HTML 로 만들고 격리된 화면(sandbox iframe, 엄격한 CSP)에 띄운다. 데이터는 소스 근거로 만든 JSON 을 페이지에 넣고 근거 링크를 유지한다. 공유는 노트북 접근 권한을 그대로 따른다(공개 URL 없음).
- **결정 필요**: 생성 HTML 의 허용 범위(입력 폼·저장 허용 여부), 내려받기 허용 여부.

### N1-9 코드 실행 환경 (별도 결정)

- **목적**: XLSX·CSV 소스를 코드로 집계·차트화한다.
- **최소 조건**: 노트북별 격리 실행(컨테이너, 네트워크 차단, CPU·메모리·시간 제한), 입력은 소스 스냅숏만, 실행 코드·결과의 감사 기록, 결과는 소스 근거와 함께 표시. ARM64(ysna)에서 실행 가능한지 확인.
- **결정 필요**: 운영 부담과 비용, 실행 엔진(Python 고정 여부), 허용 라이브러리 목록. 이 WO 에서는 구현하지 않는다.

| 2 | N1-2 질문 도구 토글(마이그레이션 1개), N1-4 개요·추천 질문 | 중간 | 1 |

각 단계는 로컬 시험 → PR 자동 병합 → ysna 배포(별도 승인) → 실제 화면 확인 순서를 따른다. 단계마다 사용자 설명서 해당 절을 함께 고친다.

## 6. 공통 규칙

- 근거 원칙(WO-C1): 지식 질문은 소스·승인 지식·지식 연결 근거로만 답한다. 새 기능도 근거 없는 문장을 만들지 않는다.
- 외부 전송: 모든 모델·웹 호출은 기존 외부 전송 판정을 거친다. 새 우회 경로를 만들지 않는다.
- 화면: `DESIGN.md` 의 토큰·글자 크기·영문 머리말 금지 규칙을 따른다.
- 기록: 새 동작은 감사 이벤트에 남기되 질문 원문·비밀값은 남기지 않는다.
