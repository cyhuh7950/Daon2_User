# WO-N9 데이터 집계 설계서

- 상태: 설계 승인(신산님 2026-11-25)
- 출처: WO-N1 후보 N1-9 "코드 실행 환경"을 신산님 결정(2026-11-25)으로 "허용된 연산만 실행하는 데이터 집계"로 좁힘
- 대화 결정(신산님 2026-11-25)
  - 첫 사용 사례: 보험 업무 엑셀 집계
  - 근거 원칙 유지, 계산값 구분 표시
  - 1차 범위: 파일 하나 안의 집계
  - 모델은 조건만 제안, 서버가 허용 연산만 실행
  - 스튜디오 새 산출물(2번안), 자체 집계기(A안)
  - 검토 뒤 결정: 큰 XLSX는 '집계 전용' 소스(대화 질문 근거에서 제외), 모델에 열 값 목록을 보내지 않음
- 코드 수정은 이 설계서 승인 뒤 구현 계획을 거쳐 한다.

## 1. 목적과 이유

보험 업무 담당자가 익명화한 청구 내역 같은 표 자료(XLSX·CSV)를 노트북에 올리고, 요청 글 하나로 집계표와 차트를 얻는다.

- 예: "월별·상품별 청구 건수와 지급액 합계를 표와 차트로 보여줘. 전월 대비 증감률도 알려줘"

지금 Daon은 "소스에 없는 숫자는 쓰지 않는다"가 원칙이다. 집계값은 정의상 소스에 없는 새 숫자다. 그래서 이 기능은 **계산값을 원본값과 구분하고, 어떤 셀·필터·식으로 나왔는지 누구나 다시 확인할 수 있게** 만드는 것이 핵심이다.

## 2. 목표 / 비목표 / 실패로 보는 것

**목표(1차)**
- 업로드한 표 파일 **한 개**에서 다음을 한다.
  - 필터
  - 묶어서 집계: 그룹(열 값), 월 단위 날짜 묶기
  - 집계 함수: 합계, 건수, 평균
  - 전기 대비 증감률(전월 대비 등)
  - 기본 차트: 막대, 선
- 결과의 모든 계산값에 **계산값** 표시를 붙이고, 아래를 확인할 수 있게 한다.
  - 사용한 파일, 시트, 셀 범위(CSV는 행·열)
  - 적용한 필터
  - 계산식
- 차트는 검증된 집계표와 **같은 데이터**만 쓴다.
- 결과를 XLSX·CSV로 내려받는다(계산 근거 포함).

**비목표(1차)**
- 서로 다른 파일 결합(조인)
- 임의 코드 실행
- 외부 데이터 조회
- 대화로 고치기: 1차는 요청을 바꿔 다시 생성만 한다
- 피벗 열 펼치기, 사용자 정의 수식, 표준편차 등 고급 통계, 예측

**실패로 보는 것**
- 계산 근거(범위·필터·식)를 확인할 수 없는 숫자가 결과에 나옴
- 0으로 나누기 등 계산할 수 없는 값을 임의의 숫자로 채움
- 차트의 값과 집계표의 값이 다름
- 모델이 쓴 문장 안에 검증되지 않은 숫자가 들어감
- 다른 노트북이나 다른 판의 자료가 계산에 섞임

## 3. 제약

**근거 원칙**
- 원본값: 원본 셀 그대로의 값. 기존처럼 근거 위치를 단다.
- 계산값: 서버가 허용된 연산으로 계산한 값. 반드시 계산 근거를 단다.
- 이 둘을 화면과 내려받은 파일 모두에서 구분해 표시한다.

**격리**
- 실행하는 것은 코드가 아니라 서버가 검사한 **집계 조건(데이터)** 뿐이다.
- 입력은 그 노트북, 고른 소스, 그 판의 원본 파일뿐이다.
  - 저장소의 원본을 해시로 확인한 뒤 읽는다(기존 인용 원본 확인 방식과 같다).
- 자원 한도를 둔다: 파일 크기, 행·열 수, 결과 묶음 수, 실행 시간. 넘으면 정해진 오류로 멈춘다.
- 네트워크, 파일 시스템 쓰기, 외부 프로세스를 쓰지 않는다.

**실행 기록**
- 산출물 판마다 다음을 저장한다.
  - 집계 조건 원문(모델 제안과 서버 정규화본)
  - 입력 소스 판과 해시
  - 결과 요약 해시
  - 실행 시간과 처리한 행 수
- 실행은 기존 감사 기록(security_audit_events)에도 남긴다.

**외부 전송**
- 모델 호출은 기존 `StudioEgressGate`를 거친다.
- 모델에는 열 이름, 서버가 판단한 열 종류, 행 수만 보낸다. **셀 값과 값 목록은 보내지 않는다**(신산님 결정).
- 요청 글에 적힌 필터 값(예: "암보험만")은 서버가 그 열에 실제로 있는 값인지 확인한다. 없으면 "그런 값이 없습니다: 암보험(상품)"으로 실패하고, 값 목록은 화면에만 보인다(외부로 보내지 않음).

**운영**
- ysna(ARM64)에서 동작해야 한다.
- 새 의존성·새 컨테이너·새 외부 서비스는 두지 않는다(A안).

**화면**
- 창 배치 원칙: 칸 안에서만 스크롤하고, 페이지 전체 스크롤은 없다.
- 문구는 `studio-messages.ko.js`에 모은다.

## 4. 만드는 방법(검토한 것과 선택)

**어디서 쓰나**
- 1안: 대화 답변 안에 표·차트
- **2안(선택): 스튜디오 새 산출물 "데이터 집계"**
  - 판 관리, 내려받기, 다시 생성, 감사 기록, 작업 큐를 기존 구조 그대로 쓴다.

**계산 엔진**

| 방법 | 내용 | 판단 |
| --- | --- | --- |
| **A. 자체 집계기(선택)** | 서버가 집계 조건(JSON)을 검사하고 Python 표준 기능(`decimal`)으로 직접 계산. 기존 스튜디오 작업자 안에서 한도를 두고 실행 | 새 의존성·ARM64 부담 없음. 묶음마다 들어간 행을 정확히 알아 셀 범위 근거가 쉬움 |

## 5. 정한 동작

### 5.1 표 자료 읽기(새로 필요)

현재 상태와 문제:
- 지금 XLSX 읽기(`xlsx_source.read_xlsx`)는 시트당 값 있는 셀 2,048개, 구조 정보 32 KB를 넘으면 거부한다.
- 그래서 1,000행 × 8열(8,000셀) 청구 내역도 올라가지 않는다.
- CSV는 글 소스로 다뤄 행·열 구조가 없다.

정한 것:
- 집계용 **표 읽기**를 따로 만든다.
  - XLSX: 시트를 고르고, 첫 행을 머리글로 본다.
  - CSV: 인코딩 UTF-8(BOM 포함)과 CP949, 구분자 쉼표·탭.
  - 결과: 열 이름, 열 종류(날짜·숫자·글자), 행 목록. 행마다 원본 위치(시트·행 번호, CSV 행 번호)를 기억한다.
- 한도(제 판단, 만드는 사람이 측정 후 조정):
  - 파일 20 MB
  - 행 100,000
  - 열 100
  - 결과 묶음 2,000
  - 실행 60초
- 숫자 해석
  - 쉼표가 든 숫자, 원 단위 표기, 음수 괄호표기를 숫자로 읽는다.
  - 숫자로 못 읽는 칸은 "숫자 아님"으로 세고 결과에 개수를 보인다. 조용히 0으로 바꾸지 않는다.
- 날짜 해석
  - XLSX 날짜 서식 값, `YYYY-MM-DD`·`YYYY.MM.DD`·`YYYY/MM/DD` 글을 날짜로 읽는다.
  - 못 읽으면 "날짜 아님"으로 센다.
- 머리글: 설정 창의 **머리글 행 번호**(기본 1)를 머리글로 본다. 그 위 행은 건너뛴다. 이름이 같은 열은 뒤에 `_2`, `_3`을 붙여 구분하고, 빈 머리글은 `열 C`처럼 열 위치로 이름 붙인다(제 판단).
- 큰 XLSX를 소스로 받는 문제(신산님 결정)
  - 지금은 2,048셀을 넘는 XLSX가 소스 처리에서 실패한다. 이 한도는 질문용 셀 근거 색인의 한도다.
  - 한도를 넘는 XLSX는 **집계 전용 소스**로 받는다.
    - 원본 보관과 해시 기록은 다른 소스와 같다.
    - 대화 질문의 근거(색인·검색)에서는 빠진다. 일부만 색인하면 뒤쪽 행을 못 본 채 틀린 답을 낼 수 있기 때문이다.
    - 소스 목록에 "집계 전용" 표시를 하고, 이 소스만 골라 질문하면 "이 표는 데이터 집계에만 쓸 수 있습니다"를 보인다.
  - 한도 안의 XLSX는 지금처럼 질문 근거와 집계에 모두 쓴다.
  - CSV는 지금처럼 글 소스로 질문에 쓰되, 집계에서는 표 읽기로 다시 읽는다. CSV에는 집계 전용 상태가 필요 없다.
  - 소스 처리 상태 값과 화면 표시는 기존 상태 흐름에 맞춰 만드는 사람이 정한다(§6).

### 5.2 만들기 흐름

1. 스튜디오 **데이터 집계** 타일을 누르면 설정 창이 열린다(웹 페이지와 같은 방식).
   - **요청 글**: 필수, 최대 2,000자
   - **표 소스**: XLSX·CSV 소스 한 개
   - **시트**: XLSX일 때만
   - **머리글 행 번호**: 기본 1
2. 카드 진행 문구: "표 읽는 중" → "집계 조건 만드는 중" → "계산 중" → 완료.
3. **표 읽기**: 서버가 원본을 해시로 확인해 읽고 열 정보를 만든다.
4. **조건 제안(모델)**
   - 모델에 요청 글과 열 정보만 주고, 집계 조건 JSON을 받는다.
5. **조건 검사(서버)**
   - 열 이름이 실제로 있는지, 연산이 허용 목록에 있는지, 종류가 맞는지(합계·평균은 숫자 열) 확인한다.
   - 어긋나면 이유를 붙여 한 번 다시 묻고, 그래도 어긋나면 실패한다(`STUDIO_VALIDATION_FAILED`).
   - 요청에 1차 범위 밖 내용(다른 파일, 외부 자료, 임의 계산)이 있으면 그 부분은 하지 않는다(제 판단).
     - 할 수 있는 부분이 있으면 그것만 계산해 완료하고, 결과 위에 경고로 "하지 않은 요청: …"을 보인다.
     - 할 수 있는 부분이 하나도 없으면 실패한다("이 요청은 데이터 집계 1차 범위에서 할 수 없습니다").
6. **계산(서버)**: 허용 연산만 `decimal`로 계산한다.
7. **저장**: 판 내용에 집계 조건, 집계표, 계산 근거, 차트 정의, 경고를 함께 저장한다.

### 5.3 허용 연산(1차)

| 단계 | 허용 |
| --- | --- |
| 필터 | 열 값 같음·다름·포함(목록), 숫자 크다·작다·범위, 날짜 기간. 여러 조건은 모두 만족(AND)만 |
| 묶기 | 글 열 값으로 묶기(최대 2개 열), 날짜 열을 월 단위로 묶기 |
| 집계 | 건수, 합계, 평균(숫자 열) |
| 비교 | 전기 대비 증감률: 시간 묶기(월)가 있을 때만, 같은 다른 묶음 값 안에서 바로 앞 달과 비교 |
| 정렬·자르기 | 집계값 또는 묶음 기준 정렬, 상위 N개(최대 50) |
| 차트 | 막대, 선. x축은 묶음 열, 값은 집계표의 한 열 |

**계산 규칙**
- 증감률 = (이번 값 − 전기 값) ÷ 전기 값 × 100. 표시는 소수 첫째 자리까지 사사오입(ROUND_HALF_UP), 저장은 정확한 값으로 한다(제 판단).
- 전기 값이 0이거나 없으면 **계산 불가**로 표시하고, 이유("전월 값 0", "전월 자료 없음")를 남긴다.
- 평균의 대상 행이 0개면 **계산 불가**.
- 숫자 아님·빈칸은 합계·평균에서 빼고, 뺀 개수를 근거에 적는다. 건수는 행 수를 센다.
- 금액 합계는 원본의 소수 자릿수를 유지한다. 반올림은 표시에서만 한다. 평균 표시도 소수 첫째 자리 사사오입.
- 한 열에 단위·통화가 섞인 경우(예: 원과 달러)는 1차에서 지원하지 않는다. 숫자로 읽히면 그대로 더하므로, 요청 전에 사용자가 열을 확인한다는 안내를 설명서에 넣는다.

### 5.4 결과 형식과 계산 근거

- **집계표**
  - 묶음 열(원본값) + 집계 열(계산값)
  - 칸마다 계산값/원본값 구분 표시
  - 계산 불가는 값 대신 "계산 불가"와 이유
- **계산 근거**(칸마다 열어 볼 수 있음)
  - 파일 이름, 시트
  - 사용한 원본 범위
    - XLSX: 시트·열·행 묶음, 예: `청구내역!F2:F31, F45:F60`
    - CSV: 행 번호 묶음과 열 이름, 예: `행 2–31, 45–60 · 지급액`
    - 범위가 길면 묶음 수만 보이고 펼쳐서 전체를 본다.
  - 적용한 필터(사람이 읽는 문장)
  - 계산식, 예: `합계(지급액) where 상품=암보험, 월=2026-03`
  - 대상 행 수, 제외한 칸 수와 이유
- **저장 형식**(제 판단)
  - 기존 인용 근거(S1… 근거 목록)와는 별도로, 판 내용 안에 칸별 계산 근거를 저장한다.
  - 원본 범위는 연속 행을 묶은 압축 표기로 저장한다.
  - 판 크기 한도(2 MiB)를 넘으면 "결과가 너무 큽니다. 조건을 좁혀 다시 생성해 주세요"로 실패한다.
  - 판에는 입력 소스 판 번호와 원본 해시를 기록한다. 소스가 새 판으로 바뀌면 다른 산출물처럼 "소스가 바뀜" 안내를 붙인다. 이미 만든 판은 그대로 둔다.
- **조건 요약**: 화면 위에 "적용한 조건" 한 덩어리(필터·묶기·집계·정렬)를 문장으로 보인다.
- **요약 문장**
  - 숫자가 들어가는 문장은 서버가 집계표에서 정해진 틀로 만든다(예: 최댓값·최솟값 묶음).
  - 모델이 쓴 문장은 넣지 않는다(실패로 보는 것 §2).
- **차트**
  - 서버가 집계표의 한 열에서 차트 정의를 만들고, 화면은 그 정의만 그린다.
  - 차트 값과 집계표 값은 같은 저장값에서 나온다.
  - 계산 불가 칸은 차트에서 빈 점·빈 막대로 두고 범례에 적는다.
  - 그림은 SVG로 그리며 외부 라이브러리는 쓰지 않는다.

### 5.5 보기

- 카드를 열면 위아래 배치로 보인다.
  - 조건 요약
  - 집계표: 칸 안 스크롤, 계산값 표시
  - 차트
  - 근거 칸: 고른 칸의 계산 근거
- 좁은 화면에서도 각 칸 안에서 스크롤하고, 페이지 전체 스크롤은 없다.
- 집계표 칸을 누르면 근거 칸에 그 칸의 계산 근거가 보인다.

### 5.6 고치기

- 1차는 **요청 바꿔 다시 생성**만 한다(기존 "설정 변경 후 다시 생성"). 지난 요청 글과 소스·시트가 채워진다.
- 대화로 고치기는 넣지 않는다.

### 5.7 내려받기

- **XLSX**
  - 시트 1: 집계표. 계산값 칸 옆에 "계산값" 표시 열을 둔다.
  - 시트 2: 계산 근거(칸별 범위·필터·식·제외 수)
  - 시트 3: 적용한 조건
  - 셀에는 값만 넣고 엑셀 수식은 넣지 않는다.
- **CSV**: 집계표 + 계산값 표시 열. 근거는 별도 CSV 2개를 zip으로 묶을지는 만드는 사람이 정한다(§6).
- 차트 그림(SVG/PNG) 내려받기는 1차에서 빼도 된다(§6).
- 조직 내려받기 정책을 다른 산출물과 똑같이 따른다.

## 6. 만드는 사람에게 맡기는 것

- 새 유형 이름: `data_aggregation`(화면 이름 "데이터 집계"). 기존 `data_table`(모델이 소스 글로 만드는 비교표)은 그대로 둔다.
- 집계 조건 JSON 스키마의 세부와 모델 지시문
- 표 읽기 한도의 정확한 값(ysna에서 10만 행 측정 후)
- 열 종류 판단 규칙의 세부(혼합 열 처리)
- 집계 전용 소스의 상태 값·화면 표시와 기존 소스 처리 흐름과의 연결(질문 검색에서 빼는 자리 포함)
- 근거 범위 압축 표기 방식(연속 행 묶기)
- 증감률의 비교 기준: 날짜 묶기에서 빈 달이 있을 때 "바로 앞 달"인지 "앞에 있는 달"인지. 기본은 달력상 바로 앞 달, 없으면 계산 불가.
- CSV 근거 내려받기 형식, 차트 그림 내려받기 포함 여부
- 설명서 절(2-22 데이터 집계)

## 8. 시험과 완료 기준(요약)

**서버 시험**
- 표 읽기
  - 큰 XLSX(2,048셀 초과) 읽기, 집계 전용 소스로 등록, 질문 근거에서 제외
  - 머리글 행 번호, 같은 이름 열 구분
  - CSV 인코딩 2종·구분자 2종
  - 숫자·날짜 해석, 숫자 아님 개수
  - 한도 초과 시 정해진 오류
- 조건 검사
  - 없는 열, 금지 연산, 종류 불일치를 거부하고 한 번 재시도
  - 1차 범위 밖 요청을 표시
- 계산
  - 합계·건수·평균
  - 월 묶기
  - 증감률: 전월 0 → 계산 불가, 전월 없음 → 계산 불가
  - 금액 정확성(소수 오차 없음)
- 근거
  - 칸마다 범위가 실제로 그 값을 만든 행과 일치
  - 필터·식 문장
- 차트 값 = 집계표 값
- 요약 문장의 숫자 ⊂ 집계표 값
- 격리
  - 다른 노트북 소스, 다른 판, 해시 불일치는 거부
  - 모델 전송 내용에 셀 값·값 목록 없음, 없는 필터 값은 정해진 오류
  - 일부 범위 밖 요청은 경고와 함께 완료, 전부 범위 밖이면 실패
- 외부 전송 판정 수 = 모델 호출 수
- 내려받기: XLSX 3시트, 계산값 표시, 수식 없음

**화면 시험**
- 설정 창: 요청 글 필수, 표 소스 고르기, 시트 고르기
- 계산값 표시, 계산 불가 표시
- 칸을 누르면 근거
- 칸 안 스크롤

**실서버 확인(ysna)**
- 합성 익명 청구 내역(XLSX, 1만 행 이상)과 CSV로 예시 요청을 해서 표·차트·증감률 확인
- 손으로 계산한 몇 칸과 대조
- 내려받은 XLSX 열어 보기
- 실행 시간·메모리 측정
