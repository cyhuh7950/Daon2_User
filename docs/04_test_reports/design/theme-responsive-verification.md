## 사람이 확인해야 하는 것(미검증)

- 라이트·다크 전환 시 Studio 패널·작성 마법사·알림 도구·설정 메뉴의 실제 화면(깨진 색, 겹침).
- 폭 1180px·820px·480px에서의 3면 배치와 하단 탭 동작, 가로 스크롤 유무.
- 색약 시뮬레이션(적록·청황)에서 유형 아이콘 구분과 상태 배지 식별.
- 키보드만으로 대화상자 열기·닫기·포커스 이동(자동 시험은 포커스 가둠 코드만 확인).
- 스크린리더 읽기 순서.

위 항목은 로그인한 브라우저에서만 볼 수 있으며, 확인 후 이 문서의 해당 줄을 "확인"으로 갱신한다.

## 실제 앱 셸 확인(2026-10-26, WSL 스택 + 개발용 인증 우회)

로그인 없이(`DAON_DEV_AUTH_BYPASS`, 개발 프로필 한정) WSL 스택의 실제 앱을 앱 내 브라우저로 확인했다.

| 항목 | 결과 |
| --- | --- |
| 노트북 홈에서 "새 Notebook" 생성 → 작업 화면 이동 | 확인 |
| 3면 배치(Source·대화·Studio), 헤더의 노트북 도구 | 확인(폭 1024px) |
| ⋮ 메뉴: 채팅 설정·맞춤설정·노트북 복사·채팅 기록 삭제 | 4개 항목 모두 표시 |
| 맞춤설정 저장 | 입력 포커스, 글자 수 표시, 저장 완료 문구 확인. Esc로 닫힘 |
| 노트북 복사 | Source 항목은 비활성(안 C), 복사 후 새 노트북으로 이동, 제목·맞춤설정 복제 확인 |
| 채팅 기록 삭제 | 확인 대화상자 → 삭제 시 서버에 `notebook_chat_clears` 행 생성(DB 확인), 화면 새로고침(의도된 동작) |
| 폭 375px 하단 탭 | 탭 3개(높이 44px), 가로 넘침 없음, 탭 전환 동작 |

**발견·수정**: 폭 375px에서 선택한 면이 3열 그리드의 첫 열(250px)에 갇혀 Studio 타일 글자가 잘리고 패널이 좁게 보였다. `workspace-polish.css`의 ≤820px 규칙에 단일 열 그리드를 추가했다. 수정 규칙을 실제 페이지에 주입해 패널 351px·타일 155px·가로 넘침 없음을 확인했다(배포본에는 다음 빌드부터 반영).

관찰: 좁은 화면에서 노트북 제목 위 "DAON WORKSPACE · NOTEBOOK" 문구가 우상단 상태 배지에 일부 가려진다(개발용 "Web Shell" 배지로 추정, 미조치). 맞춤설정 대화상자를 닫은 뒤 포커스가 ⋮ 버튼으로 돌아오지 않는다(미조치, 접근성 개선 후보).

아직 확인하지 못한 것: 색약 시뮬레이션, 스크린리더 읽기 순서, 820px 경계 폭, 라이트 테마의 실제 앱 셸.
