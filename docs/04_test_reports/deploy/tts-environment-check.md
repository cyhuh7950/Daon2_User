# 로컬 TTS 환경 점검(F7-02)

점검일: 2026-10-26. 서버: WSL-server(읽기 전용 확인만 했고 설치·내려받기는 하지 않았다).

## 확인한 사실

| 항목 | 값 |
| --- | --- |
| GPU | **NVIDIA GPU 없음**(`nvidia-smi` 없음). WSL 가상 3D 장치(Microsoft Basic Render Driver)만 보인다. CUDA를 쓸 수 없는 것으로 본다 |
| CPU | Intel Core Ultra 7 356H, 6개 코어가 WSL에 보인다 |
| 메모리 | 총 7.9 GiB, 확인 시점 사용 약 3.5 GiB(daon2·daon-user 등 다른 스택과 공유) |
| 디스크 | 1 TB 중 약 454 GB 여유 |
| ffmpeg | 설치됨(`/usr/bin/ffmpeg`) — 오디오 인코딩(mp3)·동영상 합성에 사용 가능 |
| Python | 3.12.3 |
| 기존 음성 이미지 | `voice-whisper-gpu`(4.3 GB), `xtts-webui:cu128`(19 GB, CUDA 전제) — 우리 스택과 무관한 다른 프로젝트의 이미지이며 GPU가 없어 재사용할 수 없다 |

## 정정(2026-10-26)

위 표의 "GPU 없음"은 **오판**이다. WSL-server에는 `nvidia-smi`가 PATH에 없을 뿐, `/usr/lib/wsl/lib/nvidia-smi`로 **NVIDIA GeForce RTX 5070 Laptop GPU(VRAM 8151 MiB, 사용 0 MiB)** 가 확인되고 Docker에 `nvidia` 런타임이 있다(`~/deploy/voice/README.md`도 RTX 5070·CUDA 12.4로 기록). 아래 "판단"의 CPU 전제와 MeloTTS 부적합 판정은 CPU 실측 기준이므로 GPU 조건에서는 다시 평가해야 한다. 기존 음성 이미지(`voice-whisper-gpu`, `voice-cosyvoice`, `xtts-webui`)는 이 GPU를 전제로 만든 것이다. 다만 VRAM 8 GiB를 다른 프로젝트와 나눠 쓴다.

## 판단(CPU 전제 — 위 정정 참고)

- 오디오·동영상은 **CPU만으로** 생성해야 한다. XTTS 같은 GPU 전제 모델은 쓸 수 없다.
- 남은 메모리가 약 4 GiB라서, TTS 컨테이너는 상한을 1~1.5 GiB로 두고 동시 1건으로 제한해야 한다(F0-12의 컨테이너 상한과 같은 방식).
- 한국어 2화자 대화 합성이 필요하다. 화자 두 명은 서로 다른 목소리(또는 같은 모델의 서로 다른 화자 ID)로 만든다.

## 후보(내려받기·설치 전이며, 라이선스와 한국어 품질은 설치 후 청취 평가가 필요하다)

| 후보 | 장점 | 확인할 점 |
| --- | --- | --- |
| MeloTTS(한국어) | MIT 라이선스, CPU 실시간 이상, 한국어 지원 | PyTorch·MeCab 사전 등 이미지가 커질 수 있음(약 2 GB), 화자가 1명이라 2화자는 속도·피치 변형 또는 다른 모델 병행 필요 |
| Piper(ONNX) | 매우 가볍고 CPU에서 빠름, 음성 파일이 작음(수십 MB) | 공식 한국어 음성 제공 여부 확인 필요(없으면 제외) |
| sherpa-onnx + VITS 한국어 모델 | ONNX 런타임만 필요, 가벼움 | 공개 한국어 모델의 라이선스·품질 확인 필요 |
| MMS-TTS(한국어, VITS) | 설치 간단 | 비상업 라이선스(CC-BY-NC)라 제품 사용 제한 가능 |

## 필요한 승인

모델 후보를 서버에 **내려받아 설치·청취 평가**하려면 외부 네트워크 다운로드와 디스크·메모리 사용이 필요하다. 어떤 후보를 시험할지와 설치 허용 여부는 사용자 결정 사항이다.
승인 전에는 오디오·동영상 생성기(F7-03~F7-05)를 구현하지 않는다.

## MeloTTS(한국어) 설치·측정 결과 (2026-10-26, 사용자 승인 후)

위치: 서버 `~/tts-eval`(독립 venv, 운영 스택과 무관). 설치 중 `fugashi` 구버전 고정 때문에 빌드가 실패해 `fugashi>=1.3.2`를 먼저 설치하고 MeloTTS는 `--no-deps`로 설치한 뒤 의존성을 따로 맞췄다(공식 요구 버전과 달라 `transformers` 5.x 등을 썼지만 합성은 동작했다).

| 항목 | 측정 |
| --- | --- |
| 화자 | 한국어 화자 1명(`KR`). **2화자 대화는 이 모델 하나로 만들 수 없다** |
| 모델 적재 | 첫 실행 약 73초(모델 내려받기 포함) |
| 합성 속도 | 짧은 문장 1개 약 9초, 첫 문장은 워밍업 포함 73초. 실시간보다 훨씬 느리다(다른 스택이 CPU를 쓰는 상태) |
| 최대 메모리 | 약 2.3 GiB — 컨테이너 상한 1~1.5 GiB 안에 들어가지 않는다 |
| 디스크 | `~/tts-eval` 약 수 GB(torch CPU 포함) |

판단: 이 서버(GPU 없음, 여유 메모리 약 4 GiB)에서 MeloTTS는 5분 분량 오디오(문장 약 60개)에 10분 이상, 메모리도 2.3 GiB가 필요해 **현재 조건으로는 부적합**하다. 남은 후보(sherpa-onnx VITS 한국어 등)는 가벼우나 한국어 모델의 라이선스(KSS 계열은 비상업)와 2화자 가능 여부를 확인해야 한다. 화자 2명 대화는 모델 2개를 쓰거나 화자 1명으로 낭독하는 방식으로 범위를 줄이는 결정이 필요하다.

## ysna-server 엔진 비교와 결정 (2026-10-26)

ysna-server(ARM64 4코어, GPU 없음, 메모리 23 GiB)의 `~/deploy/voice`에서 supertonic과 qwen3-tts(0.6B CustomVoice)를 켜고 같은 4줄 한국어 대화(A=여성, B=남성, 음성 약 20초)를 합성했다.

| | supertonic (F1·M1) | qwen3-tts (sohee·aiden) |
| --- | --- | --- |
| 합성 시간 / 음성 길이 | 9.7초 / 20.3초(RTF 0.48) | 143.9초 / 22.6초(RTF 6.38) |
| 메모리 | 약 576 MiB | 4.9~7.5 GiB(상한 8 GiB) |
| 라이선스 | BigScience Open RAIL-M(용도 제한) | Apache-2.0 표기(모델 카드 본문 미확인) |

청취 평가: 사용자가 두 엔진 모두 "괜찮다"고 평가했고 **supertonic을 기본으로** 하며 TTS 엔진은 선택 가능하게 하기로 했다. 구현 설계는 `docs/work_orders/WO-F7-tts-audio.md`(승인 대기). 라이선스 조건(Open RAIL-M)의 제품 사용 가능 여부는 확인이 남아 있다.
