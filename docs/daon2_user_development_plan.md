## 진행 상태 표기

| 표시 | 의미 | 부여 기준 |
| --- | --- | --- |
| `[0]` | 완료 | 구현이 끝났고 **완료 기준(검증)을 통과한 증거**가 있다. 증거는 비고에 커밋 SHA·테스트·배포 기록으로 남긴다. |
| `[1]` | 테스트 중 | 구현이 끝나 테스트·검증을 진행 중이거나, 일부 검증만 끝난 상태 |
| `[2]` | 개발 중 | 구현 착수 후 완료 전 |
| `[ ]` | 착수 안 함 | 구현·테스트 모두 시작 전 |

**이식 항목 규칙(2026-10-20 결정)**: daon-user에서 소스를 가져온 기능은 코딩을 생략하고 **테스트와 수정**만 진행한다. 이식된 항목은 새 환경에서 테스트를 시작하는 시점부터 모두 `[1]`로 표시하고, 완료 기준을 통과하면 `[0]`으로 바꾼다. 결함 수정이 필요하면 비고에 결함 ID·수정 커밋을 적는다.

규칙
1. 상태는 순서대로만 가지 않고 **실제 진행**을 반영한다(되돌릴 수 있다).
2. `[0]`은 증거 없이 표시하지 않는다. 단위 테스트만 통과했으면 `[1]`이다.
3. 항목을 쪼갤 때는 새 ID를 만들고 이전 ID는 취소선으로 폐기 표시한다.
4. 진도 집계는 `node scripts/plan-progress.mjs`로 하고, 아래 요약 갱신은 `--write`로 한다.

표의 열: **상태 | ID | 항목 | 설계서 | 단계 | 완료 기준·비고**
